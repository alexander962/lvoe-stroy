# Focus Board

Focus Board — учебный менеджер задач для практического изучения современной frontend-разработки на Next.js. Проект развивается поэтапно: от App Router и способов рендеринга до RTK Query, кеширования, Feature-Sliced Design и автоматических тестов.

## Технологии

- Next.js с App Router;
- React;
- TypeScript в строгом режиме;
- Sass и SCSS Modules;
- ESLint;
- Prettier.

Redux Toolkit, RTK Query, React Hook Form, Zod, Jest, React Testing Library, Storybook, Husky и Playwright будут добавляться по мере появления соответствующих учебных задач.

## Требования

- Node.js 20.9 или новее;
- npm.

## Запуск проекта

Установить зависимости:

```bash
npm ci
```

Запустить сервер для разработки:

```bash
npm run dev
```

После запуска приложение доступно по адресу [http://localhost:3000](http://localhost:3000).

## Production-сборка

Создать оптимизированную сборку:

```bash
npm run build
```

Запустить собранное приложение:

```bash
npm run start
```

Команду `start` следует выполнять после успешного `build`.

## Доступные команды

| Команда                | Назначение                                              |
| ---------------------- | ------------------------------------------------------- |
| `npm run dev`          | Запускает Next.js в режиме разработки                   |
| `npm run build`        | Создаёт production-сборку и проверяет TypeScript        |
| `npm run start`        | Запускает предварительно собранное приложение           |
| `npm run lint`         | Проверяет исходный код с помощью ESLint                 |
| `npm run typecheck`    | Проверяет типы без создания JavaScript-файлов           |
| `npm run format`       | Форматирует поддерживаемые файлы с помощью Prettier     |
| `npm run format:check` | Проверяет форматирование без изменения файлов           |
| `npm run check`        | Последовательно запускает Prettier, ESLint и TypeScript |

## Структура исходного кода

Маршруты и корневой layout находятся в `src/app`. Стили отдельных компонентов создаются как SCSS Modules с расширением `.module.scss`. Глобальные стили подключаются в корневом layout.

## Рендеринг в App Router

Проект содержит три страницы, на которых можно сравнить способы генерации HTML в production-режиме.

| Маршрут        | Режим | Когда создаётся HTML                  | Наблюдаемое поведение                                                                    |
| -------------- | ----- | ------------------------------------- | ---------------------------------------------------------------------------------------- |
| `/`            | SSG   | Во время `npm run build`              | Время генерации не меняется при обновлении страницы и обновляется после новой сборки     |
| `/server-time` | SSR   | На сервере при каждом запросе         | Время меняется после каждого обновления страницы                                         |
| `/daily-tip`   | ISR   | Статически с последующей ревалидацией | Сохранённая версия отдаётся из кеша и обновляется после истечения интервала `revalidate` |

Для проверки поведения нужно использовать production-режим:

```bash
npm run build
npm run start
```

Режим разработки не подходит для точного сравнения SSG, SSR и ISR, поскольку Next.js обрабатывает страницы в нём иначе.

## Server и Client Components

Компоненты в `src/app` являются серверными по умолчанию. Главная, страницы времени и совета, список задач и детали задачи формируются Server Components.

Client Components используются только там, где требуется браузерная интерактивность:

- мобильная навигация хранит состояние открытия и обрабатывает пользовательские события;
- фильтр задач хранит выбранный статус и вычисляет видимый список из переданных серверной страницей данных.

Директива `"use client"` ставится в файле клиентской границы. Корневой layout и страница `/tasks` при этом остаются серверными, поэтому клиентский JavaScript отправляется только для интерактивных частей.
